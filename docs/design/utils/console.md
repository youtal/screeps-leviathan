# 控制台工具设计

交付状态：

- 文本工具（模板替换、单行折叠、着色、链接）：已交付，由 `utils/console` 入口导出。
- 表单渲染器 `createForm` 与帮助渲染器 `createHelp`：实现与测试已交付；入口导出未交付（入口中保留为注释）。
- HTML 转义策略：待决，见 §6。

模块目录为 `src/utils/console`，为 Screeps 控制台生成 HTML 文本。

## 1. 定位与边界

- 只返回字符串，不调用 `console.log`，不执行命令，不访问 Memory。除 `createRoomLink`、`createForm`、`createHelp` 读取 `Game` 外，结果只由参数决定。
- Logger 单向依赖着色函数（`Color`、`dyeText`），本模块不依赖 Logger。表单、帮助面板与房间链接属于工具，不进入内核职责（见 [Logger 设计 §1](../core/logger.md)）。

## 2. 控制台约束

- 控制台以 HTML 渲染输出内容，并按换行把一次输出拆成多条消息。面板类输出因此必须折叠为单行：`fixRetraction` 删除全部 `\n`。
- 折叠后内嵌脚本与其余内容处于同一行：脚本不能使用 `//` 行注释，语句必须显式以分号结束。
- 表单按钮通过游戏网页客户端的内部服务（`angular.element(document.body).injector().get('Console').sendCommand`）执行命令。这不是公开接口，客户端改版可能使按钮失效。

## 3. 模板

- 模板以 `.html` 文件维护。构建时由 htmlString 插件压缩为默认导出的字符串（删除注释、折叠空白、压缩 CSS）；Jest 中由 `test/support/htmlTransform.cjs` 提供同样形式的导出（只删除注释）。
- 一个模板文件包含多个片段，以 `;;` 分隔。渲染器在模块加载时切分一次，按位置解构：表单 7 段，帮助 4 段。片段的数量与顺序是模板与渲染器之间的约定，TypeScript 无法检查，由测试检查。
- 占位符写作 `{name}`，由 `replaceHtml` 替换：键按字面量匹配，值按字面量插入（`$&` 等替换模式不生效）；按键的顺序逐个替换，替换结果中出现的后续占位符会继续被替换；映射中没有的占位符原样保留。

## 4. 表单

- 支持 input、select、checkbox、radio 四种控件。控件构造器表是映射类型，每种控件类型都必须有构造器，新增类型时缺少实现会成为编译错误。
- 表单的 DOM 名称为表单名加 `Game.time`，不同 tick 打印的同名表单互不干扰；同一 tick 内同名表单会冲突。
- 提交时，按钮脚本按字段名收集取值（checkbox 收集为选中值数组，其余控件取单个值），序列化为 JSON，把 `(command)(json)` 交给控制台执行。`command` 由调用方提供，必须是在控制台中求值为函数的表达式。

## 5. 帮助面板

- 结构为“模块 → API 列表”。每个 API 是一个折叠面板，由 checkbox 的选中状态与 CSS 控制展开，不含脚本。折叠控件 id 为函数名加 `Game.time`。
- 调用形式：普通函数显示为 `name(参数…)`；`commandType` 为 true 时显示为属性式命令，不带括号。

## 6. 信任边界

- 所有文本（标签、选项、描述、命令、URL）都不做 HTML 转义，也不按属性或脚本字符串转义。表单名与字段名还会进入内嵌脚本的字符串字面量，命令会进入脚本中的模板字符串。
- 因此调用方只能传入可信文本，并遵守各参数的字符限制（见 [使用说明](../../usage/utils/console.md)）。
- 待决设计事项：是否在本模块内转义、在哪一层转义（文本、属性、脚本字符串三种上下文的规则不同），以及对命令字符串做何种约束。

## 7. 性能与生命周期

- 模板片段在模块加载时切分一次，随 global 驻留 heap，global reset 后重建。
- 渲染只在调用时发生，每个占位符做一次全局正则替换，成本与模板长度和占位符数量成正比；不缓存渲染结果。
- 这些工具服务于人工交互，不应进入每 tick 的热路径。
