# PriorityQueue 设计

交付状态：已交付。

`PriorityQueue<T>` 是通用的二叉堆优先队列，服务于需要反复取出最高优先级元素的算法，例如寻路的开放列表。源码为 `src/utils/priorityQueue.ts`，经 `utils` 入口导出。

## 1. 协议

- 比较器 `comparator(pre, nxt)` 返回 true 表示 `pre` 的优先级高于 `nxt`，排序方向完全由调用方决定：返回 `a < b` 得到最小堆，返回 `a > b` 得到最大堆。
- 比较器必须自洽：满足传递性，且同一对元素不能互相判定为更高。否则出队顺序不再有保证。
- 优先级相同的元素出队顺序不稳定。需要确定性顺序时，在比较器中加入次级比较键。
- 元素入队后，不得修改影响比较结果的字段。队列不提供调整优先级的操作。

## 2. 算法与复杂度

用数组表示完全二叉树，下标 `i` 的子节点为 `2i+1`、`2i+2`，父节点为 `floor((i-1)/2)`，下标 0 始终是最高优先级元素。

| 操作 | 做法 | 复杂度 |
| --- | --- | --- |
| 构造 | 复制输入数组后，自最后一个非叶节点向根逐个下沉（Floyd 建堆） | O(n) |
| `push` | 追加到末尾后上浮 | O(log n) |
| `pop` | 根与末尾交换、弹出，再从根下沉 | O(log n) |
| `peek`、`size`、`isEmpty` | 直接读取数组 | O(1) |
| `clear` | 把数组长度截断为 0 | O(1) |

成批放入初始元素时，Floyd 建堆比逐个 `push`（O(n log n)）更省，因此构造函数接受初始数组。

## 3. 所有权与状态

- 构造时浅拷贝输入数组。之后的操作只修改队列自己的数组，调用方的数组不会被重排；元素本身不复制。
- `clear` 保留内部数组，只释放元素引用，适合每 tick 复用同一个队列实例。
- 状态只在实例 heap 中，不访问游戏环境或 Memory。实例可以跨 tick 保留，global reset 后由调用方重新创建。

## 4. 失败与边界

- 比较器不是函数时，构造阶段立即抛错，避免堆序在之后静默失效。
- 队列为空时，`pop` 与 `peek` 返回 `undefined`，与 `Array.prototype.pop` 一致。元素本身可以是 `undefined` 时，调用方需要用 `size` 或 `isEmpty` 区分。
- 初始数组可以省略（传入 `undefined`），得到空队列。

## 5. 性能取舍

交换两个节点使用解构赋值，每次交换创建一个两元素的临时数组，以少量分配换取可读性。如果性能剖析显示交换是热点，可以改为显式临时变量。
