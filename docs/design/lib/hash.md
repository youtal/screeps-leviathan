# 模块设计：hash（稳定哈希）

| 项目 | 内容 |
| --- | --- |
| 源码 | `src/lib/hash/` |
| 架构章节 | 4.5 hash、9.2 命名规范（校验位）、12.2 错峰 |
| 成熟度 | 定稿 · M1 |

## 1. 职责

把字符串映射为 32 位无符号整数，供以下用途：

| 用途 | 形式 | 使用方 |
| --- | --- | --- |
| 名称校验位 | `hashString(正文 + salt) % 36` | [naming](./naming.md) |
| 周期任务错峰 | `(Game.time + hashString(id)) % N === 0` | kernel.cpu 的维护层（5.2）及各周期任务 |
| 按键分片 | `hashString(房间名) % 页数` | segments 的情报分片（6.8，M4） |

不是密码学哈希，不承担防伪：校验位只用于把本系统的名称与外来名称区分开（9.2）。

## 2. 算法与稳定性

FNV-1a 32 位逐 UTF-16 码元累乘，再做 MurmurHash3 的 fmix32 收尾：

```text
h = 0x811c9dc5
对每个码元 c：h = imul(h ^ c, 0x01000193)
h ^= h >>> 16; h = imul(h, 0x85ebca6b); h ^= h >>> 13; h = imul(h, 0xc2b2ae35); h ^= h >>> 16
返回 h >>> 0
```

- **收尾混合的理由**：调用方常取小模数（36、错峰周期 N）。FNV-1a 对末位字符的变化扩散到低位较弱，而相邻序号、相邻 tick 的名称恰好只差末尾几个字符。fmix32 使每个输入位影响全部输出位，小模数下的分布接近均匀。
- **稳定性**：校验位写在 creep 与 spawn 的名称中，随实体跨 global reset、跨版本保留；Memory 丢失后的认领（11.6）也依赖它。因此算法一经发布不能修改，测试以固定向量冻结结果。需要不同分布时新增函数，不改动 `hashString`。
- **码元而非字节**：直接使用 `charCodeAt`，不做 UTF-8 编码，避免分配；结果只依赖字符串内容，与 V8 版本无关。

## 3. 接口与用法

```ts
hashString(text: string): number   // 0 … 2^32 − 1
```

- 不抛错，不分配对象；成本为每个码元一次异或与一次 `Math.imul`。
- 取模时直接对结果取模即可，结果非负。

## 4. 验证

单元测试覆盖固定向量（另经独立的 Python 实现核对）、结果范围，以及 36 000 个相邻名称在模 36 与模 10 下的分布（每桶偏离均值分别不超过 15% 与 5%）。
