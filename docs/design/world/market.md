# 模块设计：物价模型（world.market）

| 项目 | 内容 |
| --- | --- |
| 源码 | `src/world/market/`（未实现） |
| 所属架构章节 | 架构设计 7.7 market |
| 成熟度 | 方向（M6 实施前细化） |
| 日期 | 2026-10-16 |

物价模型把市场历史和当前挂单转换为每种资源的可实现价格及其不确定度。接口与职责见架构设计 7.7。

## 1. 数据来源

| 数据 | 来源 | 刷新 | 存放 |
| --- | --- | --- | --- |
| 每日成交统计：日期、笔数、成交量、量加权均价、量加权标准差 | `Game.market.getHistory(r)` | 每种资源每个游戏日一次（日期变化时） | segment |
| 挂单簿 | `Game.market.getAllOrders({resourceType})` | 只对候选资源轮转采样，每 tick 至多 `N_BOOK` 种，同一资源间隔 `T_BOOK` | heap |
| 本方成交 | `Game.market.incomingTransactions` / `outgoingTransactions` | 每 `T_BOOK` | 统计 |

`getAllOrders` 是主要 CPU 消耗，因此只采样出现在候选配方中的资源，并放在规划层执行。

## 2. 价格估计

对每种资源 r：

| 量 | 定义 |
| --- | --- |
| 公允价 P̂ | 按成交量加权、以半衰期 `H` 天指数衰减的 `avgPrice` 均值 |
| 波动 σ | σ² = 量加权的 `stddevPrice`² 均值 + `avgPrice` 的日间方差 |
| 流动性 L | 近 7 日日均成交量；日均笔数低于 `N_MIN` 的资源视为薄市，不参与规划 |
| 买入价 B(q) | 卖单按价格升序累计到数量 q 的加权均价，加运输能量成本（按 P̂_energy 折算后除以 q）；无可用卖单时取 P̂ + 2σ |
| 卖出价 S(q) | 买单按价格降序累计到数量 q 的加权均价，减运输能量成本；无可用买单时不计划出售 |

- **运输能量**：`ceil(q × (1 − e^(−距离/30)))`，距离为房间间的路线距离。
- **异常挂单**：价格偏离 P̂ 超过 `m·σ` 的挂单在累计时剔除，防止误挂单或操纵。
- **流动性上限**：每个计划周期内，同一资源的计划买卖量不超过 `α × L × 周期天数`，避免自身交易推动价格。
- **成交方式**：估价以即时成交（`deal`）为准。挂单需付 5% 手续费且成交时间不确定，只作为可选策略单独评估。

## 3. 可用性

市场为空或有效历史少于 `D_MIN` 天时（私服常见），`available` 为假，所有消费者退回各自的无市场行为。

## 4. 验证

- 以录制的市场历史与挂单簿为输入做单元测试，覆盖薄市、异常挂单、无挂单。
- 线上对比"估计的可实现价"与"实际成交价"，偏差写入统计。

## 5. 参数

| 参数 | 默认值 |
| --- | --- |
| `N_BOOK` / `T_BOOK` | 每 tick 2 种 / 同一资源 500 tick |
| `H`（价格半衰期） | 3 天 |
| `N_MIN`（薄市阈值） | 日均 10 笔 |
| `m`（异常挂单剔除） | 3σ |
| `α`（流动性上限） | 日均成交量的 20% |
| `D_MIN`（最少有效历史） | 3 天 |
