# 模块设计：产业规划（domains/industry/economics）

| 项目 | 内容 |
| --- | --- |
| 源码 | `src/domains/industry/economics/`（未实现） |
| 所属架构章节 | 架构设计 9.8 产业规划 |
| 成熟度 | v1 方向（M6 实施前细化）；v2 候选（由对账数据触发） |
| 日期 | 2026-10-16 |

产业规划以物价模型（架构设计 7.7）为输入，为每个生产设施选择配方，并输出生产计划与采购、出售清单。职责与接口见架构设计 9.8。

## 1. 生产图

- 节点是资源，边是配方，分三类：
  - **lab 反应**：两种原料各 5 单位生成 5 单位产物，每批耗时为该产物的反应时间；
  - **工厂商品**：按配方投入原料，经冷却时间产出，高等级商品要求工厂达到对应等级；
  - **压缩与解压**：工厂配方中互为逆运算的一对。
- 压缩与解压互逆使图中存在环，因此只评估长度不超过 `D` 且资源不重复的生产链。
- 设施：每个 factory 按等级区分；每组 lab 集群由 2 个原料 lab 和 k 个产出 lab 组成。

## 2. v1：白名单 + 毛利阈值

```text
单批毛利    π = Σ 产出数量 × S(产出) − Σ 原料数量 × c_in − 能量 × P̂_energy
毛利率      π / (Σ 原料数量 × c_in + 能量 × P̂_energy)
```

- 只在**配置的配方白名单**中选择。
- 原料成本 c_in：库存中高于目标的部分按机会成本 S 计；不足的部分按买入价 B 计。
- 毛利率低于 `M_MIN` 的配方不生产。
- 每个设施选择满足约束的配方中毛利率最高的一个；新方案必须比当前方案高出 `h` 并保持一个评估周期才切换。
- 约束：买卖量受物价模型的流动性上限限制；能量受 governor 预算限制；工厂等级匹配；库存控制的目标库存视为预留，出售只能动用高于目标的盈余。

## 3. v2：风险调整收益率（候选）

```text
单批时间    τ = 工厂冷却时间，或 反应时间 × 批量 / (5 × 产出 lab 数)
收益率      ρ = π / τ                               （货币 / tick）
风险调整    ρ̃ = ρ − λ × σ(π) / τ
自制成本    c_make(r) = Σ 原料 min(B(原料), c_make(原料)) + 能量 × P̂_energy
```

- σ(π) 由各产出与原料的 σ 按数量合成，假定价格相互独立。
- 求解：全部"设施 × 配方"按 ρ̃ 降序依次分配，同步扣减共享的流动性额度与能量预算；ρ̃ ≤ 0 的设施闲置或改为维持 boost 库存。
- 允许多级生产链（原料取"买入"与"自制"中较低者）。
- **启用条件**：v1 运行满 `T_RECON` 天后，产业规划的预测毛利与实际成交毛利的平均相对偏差低于 `RECON_ERR`。否则说明价格估计还不够可靠，继续使用 v1。

"单位时间货币收益最有可能最优"在 v2 中的含义是：在当前估计下选择风险调整后期望收益率 ρ̃ 最高的组合；λ 越大越偏向价格稳定、流动性好的配方。

## 4. 评估时机

每日历史更新时，以及采样价格变化超过 2σ 时，在规划层执行。

## 5. 输出

| 清单 | 内容 | 消费者 |
| --- | --- | --- |
| 生产计划 | `{facility, recipe, batches, until}` | labs、factory |
| 采购清单 | `{resource, qty, maxPrice, room}` | market |
| 出售清单 | `{resource, qty, minPrice, room}` | market |

market 只在实际成交价满足 `maxPrice` / `minPrice` 时成交，否则不执行并回报原因。每次评估的价格估计与候选排名写入统计，并与实际成交对账。

## 6. 保护

- 物价模型不可用时，labs 与 factory 按配置的库存目标运行。
- 单日采购总额不超过当前货币余额的 `β`，并保留一笔最低货币储备。

## 7. 参数

| 参数 | 默认值 |
| --- | --- |
| `M_MIN`（最低毛利率） | 15% |
| `h`（切换滞回） | 15% |
| `β`（单日采购上限） | 货币余额的 10% |
| `D`（生产链最大长度，v2） | 3 |
| `λ`（风险系数，v2） | 1 |
| `T_RECON`（启用 v2 前的对账时长） | 14 天 |
| `RECON_ERR`（对账偏差上限） | 20% |
