# RoomShortcuts 设计

交付状态：房间查询、事件更新、缓存租约、超时回收、公共查询接口与服务令牌已交付；核弹及通用失效事件接入未交付。

RoomShortcuts 为有视野的房间建立建筑、Source 和 Mineral 的 ID 缓存。集合查询无结果时返回 `[]`，单对象查询无结果时返回 `undefined`；房间尚未建设某类建筑属于正常状态，不记录警告。

公共出口发布 `RoomShortcuts` 接口与 `RoomShortcutsService` 令牌：消费者只取得查询方法，缓存清扫 `sweep` 属于提供者自身的维护入口。令牌只绑定服务名与类型，不改变缓存生命周期、插件依赖或事件协议。

建筑索引来自 `FIND_STRUCTURES`，包含房间内所有可见建筑，不按所有者过滤：有视野的他人房间返回他人的建筑，无主建筑（道路、墙、container 等）同样计入。所有权判断属于调用方，索引对己方和他方房间保持同一语义。使用方法见 [使用说明](../../usage/modules/roomShortcuts.md)。

模块插件不声明持久化。房间索引、初始化时间和 5000 tick 租约由模块闭包维护，不占用 RawMemory；global reset 后按首次查询重建。业务缓存数据不进入持久化：它是可以按需重建的派生数据，持久化会占用主 Memory 的容量预算、加重每次装载与写盘的成本，收益只是省下 reset 后的重新扫描。

## 容量与回收

缓存不设容量上限，改用超时回收把占用收敛到“最近一个租约内查询过的房间”：

- **超时即租约到期。** 超过租约的索引不会再被读取：有视野时下一次查询必定重扫并整体替换，没有视野时查询直接删除它。因此淘汰门限与租约共用一个值，不另设 TTL。
- **回收时机。** 索引只在被查询时才会重建或删除，只查询过一次的房间会一直留在 heap 中，所以需要一个不依赖查询的时机：插件在自己的 `onTickBegin` 中按固定间隔清扫，遍历全部房间删除已超时的索引。CPU 不足时跳过，回收可以推迟。条目最长驻留“租约 + 清扫间隔”。
- **异常起点按超时处理。** 起点不是有限数，或起点晚于当前 tick（私服回档使 `Game.time` 倒退），都判定为已超时，使缓存重新扫描而不是永不刷新。清扫在 tick 倒退时立即执行。
- **无视野告警标记同样回收。** 标记记录最近一次无视野查询的 tick，闲置超过一个租约即删除；该房间之后再被查询时会重新告警一次。
- **超时的索引不再被事件维护。** 建成与摧毁事件落在已超时的房间上时直接忽略，避免为不会再被读取的索引支付一次对象查询，也避免把已失效的数据改写成看似新鲜的样子。

## 缓存更新

- 模块创建时全局订阅一次 `structure:built` 和 `structure:destroyed`，不随房间缓存的初始化重复订阅。建筑事件携带 `roomName`，模块据此更新对应房间。
- `structure:built` 用于把新建筑加入对应类型缓存。
- `structure:destroyed` 同时携带来源房间、原建筑 ID 和 Ruin ID。订阅者读取 Ruin，校验房间和原建筑 ID 后局部删除缓存；无法读取 Ruin 或校验失败时废弃对应房间缓存。
- getter 发现房间当前没有视野时废弃缓存。恢复视野后的首次查询会重新初始化。
- 无视野告警按房间限频：房间每次失去视野后的第一次 getter 调用记录一条 `warn`，其后的重复调用静默返回空值；房间再次有视野时清除标记，下一次失去视野重新告警。无视野不使用 `error` 等级。
- 每次完整初始化记录当前 tick。缓存租约默认持续 5000 tick；到期后的首次 getter 会重新扫描该房间并开始新租约。可通过 `cacheLeaseTicks` 调整。
- `forceReInit` 用于诊断和测试。启用后每次 getter 都重新扫描房间，不应作为生产环境默认值。

## 已接受风险

如果房间失去视野期间没有调用任何 getter，模块无法立即观察到这次视野中断。恢复视野后，旧缓存可能继续使用到租约到期；失效对象会被过滤，但期间新增的建筑可能延迟出现。租约提供最终一致性，可通过房间视野生命周期管理缩短漂移窗口。

核弹落地不会生成 Ruin，并且会删除已有 Ruin，因此无法满足 `structure:destroyed` 的双 ID 协议。后续引入核弹消息类型时，RoomShortcuts 应订阅该消息并直接废弃目标房间缓存。

房间事件日志只提供被销毁对象的 ID 和类型，不直接提供 Ruin ID。事件发布者需要及时扫描 `FIND_RUINS`，通过 `ruin.structure.id` 匹配原建筑并取得 Ruin ID。失去房间视野、事件处理延迟或 Ruin 已经消失时，发布者无法组成双 ID；此时不得伪造 ID，应通过后续的通用失效事件或房间生命周期机制废弃缓存。

## 租约兜底

租约按完整初始化时间计算，因此不同时间开始使用的房间会自然分散刷新。单纯统计“已经发生的失效次数”不能发现没有事件产生的缓存漂移，所以不作为兜底触发条件。
