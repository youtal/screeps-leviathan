# goto 模块成本场设计

交付状态：未交付。成本场与方向场的数据布局、参考场索引、`cm` / `cmin` 门限与残差复用算法均为设计
意图，尚无实现。

待决设计事项：参考场复用的净收益与残差搜索的队列结构须在目标运行时实测后确定；`cm` / `cmin` 取值与
fallback 阈值需按 profile 标定；Cost Field 与 Direction Field 的缓存归属及差分存储形式须在实现前
定稿。

相关文档：[goto 模块技术设计](./goto.md)（§7 房间内 Flow Field、§7.4 流场复用）。

## 1. 目标

为 Screeps 单房间 `50×50` 地图设计一个低 CPU、可缓存、支持参考场复用的 goto / Flow Field 寻路模块。

核心数据分为：

- **成本场（Cost Field）**：记录每个位置到目标的最小累计移动成本。
- **方向场（Direction Field）**：记录每个位置朝目标移动时的下一步方向。
- **参考场索引**：帮助新目标快速找到一个高质量的已有成本场作为参考。

## 2. 成本场的数据规模

单房间共有 `2500` 个格子。采用 `Uint16Array(2500)`，每格 2 bytes，因此单个完整成本场占：

\[
2500\times2 = 5000\text{ bytes}
\]

即 **5000 B ≈ 4.88 KiB ≈ 5 KB / Cost Field**。

### 最大理论成本

若 terrain 成本按：

```text
road   = 1
plain  = 2
swamp  = 10
```

单房间最短路径作为简单路径，最多经过 2499 次移动，因此保守理论上界为：

\[
2499\times10 = 24990
\]

所以 `Uint16` 足够。若保留 `65535` 作为 `UNREACHABLE`，则最大有效成本为 `65534`。

## 3. 四种 costProfile

| Profile | Road | Plain | Swamp |
|---|---:|---:|---:|
| 道路 + 沼泽 | 1 | 2 | 10 |
| 仅沼泽 | 1 | 1 | 5 |
| 仅道路 | 1 | 2 | 2 |
| 忽略所有地形 | 1 | 1 | 1 |

原则：只需要保持不同地形之间的相对成本比例正确，不必强求不同 profile 之间绝对值一致。

理论上不同 profile 可以进一步压成 15 / 14 / 13 / 12 bit，但 JavaScript 没有对应的原生 TypedArray，额外编码复杂度不划算。

**结论：统一使用 `Uint16Array(2500)` 作为 Cost Field。**

## 4. 方向场编码

Screeps 原生方向值为 `1..8`。建议方向场采用 **4 bit / cell**：

```text
0     = 未生成 / 无有效方向 / 按策略定义
1..8  = Screeps 原生方向
9..15 = 保留
```

2500 格占：

\[
2500\times4/8 = 1250\text{ bytes}
\]

即 **1250 B ≈ 1.22 KiB / Direction Field**。

## 5. 成本场与方向场分离缓存

两者用途不同：

- Cost Field：用于新目标寻路参考、最短成本查询、landmark / differential heuristic、增量或重加权算法。
- Direction Field：用于 creep 实际移动，直接 O(1) 查询下一步方向。

因此 Cost Field 与 Direction Field 应独立缓存、独立淘汰。

## 6. 方向场生成策略

最终采用“主动 + Lazy”结合。

### 从零完整建立 Cost Field

在 Dijkstra / relaxation 中，方向可以作为副产物直接生成：

```ts
if (newCost < cost[next]) {
    cost[next] = newCost;
    direction[next] = directionFrom(next, current);
}
```

### 通过参考场增量 / 启发建立

能可靠确定方向的格子直接写入 Direction Field；不能确定的格子保持 `0`，creep 实际经过时再从成本信息求方向并写回。

## 7. 参考成本场的 O(1) 索引

每个房间、每个 `costProfile` 维护两张长度 2500 的数组：

```ts
bestField: Uint8Array(2500)
bestCost:  Uint8Array(2500)
```

其中：

- `bestField[p]`：位置 `p` 当前最优参考 Cost Field 的 ID。
- `bestCost[p]`：该参考场在位置 `p` 的成本。

因为参考资格受 `cm` 限制，`bestCost` 范围很小，`Uint8Array` 足够。若 Field ID 数量也小于 256，则 `bestField` 也可使用 `Uint8Array`。

四个 profile 合计约 **20 KB / room** 的参考索引。

## 8. `cm`：参考场有效范围

定义 `cm`：若已有成本场 `C` 在位置 `p` 满足

\[
C[p] < c_m
\]

则认为该 Cost Field 对位置 `p` 的新目标建场具有参考意义；否则视为过远。

这不是几何距离限制，而是**真实移动成本距离限制**。

新 Cost Field 建成后，不需要遍历全部 2500 格，只需要从目标出发遍历满足 `C[p] < cm` 的影响范围，并更新 `bestField / bestCost`。

## 9. `cmin`：参考场密度控制

设新场 `C'` 的 `cm` 影响范围为：

\[
A=\{p\mid C'[p]<c_m\}
\]

若：

\[
\forall p\in A,\quad bestCost[p] < c_{min}
\]

则说明 `C'` 能覆盖的所有位置都已经拥有足够优秀的参考场，因此 `C'` 对未来其他目标的参考价值很低。

是否引入 `cmin`，本质上是在权衡：用额外 CPU 换取约 5 KB Cost Field 内存。

需要注意：Direction Field 无论是否 Lazy，都已经占用约 1250 B，因此不应计入 `cmin` 的内存节省。

如果不使用 `cmin`，既然 `C'` 已经建成，让它进入参考场候选并更新索引几乎没有拒绝理由，因为更新代价很低，而未来收益可能较大。

## 10. 设计取舍：新目标不必先建立完整 Cost Field

本设计不把"先建立完整 Cost Field，再得到 Direction Field"视为新目标寻路的必经步骤。需要回答的
问题是：**能否利用已有参考 Cost Field，直接构造新目标 Direction Field，而不完整建立新目标
Cost Field？**

## 11. 数学模型：参考 Cost Field 的重加权

设：

- `R`：旧参考目标
- `T`：新目标
- `C(x)`：位置 `x` 到旧目标 `R` 的最小累计成本
- `N(x)`：位置 `x` 到新目标 `T` 的最小累计成本
- `w(x,y)`：从相邻位置 `x` 移动到 `y` 的真实一步成本
- `s(x)`：参考 Direction Field 在位置 `x` 指向的下一格

旧成本场满足 Bellman 最优关系：

\[
C(x)=\min_y[w(x,y)+C(y)]
\]

旧方向选择的下一格满足：

\[
C(x)=w(x,s(x))+C(s(x))
\]

## 12. 修正量 `Δ`

定义：

\[
\Delta(x)=N(x)-C(x)
\]

它表示目标从 `R` 换成 `T` 后，位置 `x` 的最优成本变化量。

若参考旧方向 `x → s(x)` 在新目标下仍然最优，则：

\[
N(x)=w(x,s(x))+N(s(x))
\]

与旧公式相减得到：

\[
\boxed{\Delta(x)=\Delta(s(x))}
\]

因此：若 `Δ` 在旧方向边两端相等，则旧方向仍满足新目标下的最优条件。

## 13. 残差边权 `ρ`

定义：

\[
\rho(x,y)=w(x,y)+C(y)-C(x)
\]

含义：相对于参考成本场而言，选择 `x → y` 比旧目标下的最优结构额外付出的成本。

因为：

\[
C(x)\le w(x,y)+C(y)
\]

所以：

\[
\boxed{\rho(x,y)\ge0}
\]

而对于旧方向 `x → s(x)`：

\[
\boxed{\rho(x,s(x))=0}
\]

因此参考方向树上的最优边，在残差图中全部变为 0 成本边。

## 14. 重加权场 `H`

定义：

\[
H(x)=N(x)+C(T)-C(x)
\]

由于：

\[
\Delta(x)=N(x)-C(x)
\]

所以：

\[
H(x)=\Delta(x)+C(T)
\]

`C(T)` 对所有位置是常数，因此：

\[
H(x)=H(y)\iff\Delta(x)=\Delta(y)
\]

同时可以证明：

\[
\boxed{H(x)=dist_\rho(x,T)}
\]

即 `H` 等于在残差边权 `ρ` 下，从 `x` 到新目标 `T` 的最短距离。因此可以从 `T` 出发，在残差图中运行 Dijkstra。

## 15. 为什么重加权仍然严格最优

对任意路径：

\[
x=p_0\rightarrow p_1\rightarrow\dots\rightarrow p_k=T
\]

残差路径总成本展开后为：

\[
\sum w + C(T)-C(x)
\]

其中 `C(T)-C(x)` 对固定起点 `x`、终点 `T` 是常数。

因此任意两条路径的大小关系不会改变：

\[
P_1<P_2\iff P'_1<P'_2
\]

所以残差图中的最短路径与原 CostMatrix 中的严格最短路径完全一致。

## 16. “受影响区域” A

`A` 是需要修改方向的位置集合，边界外直接复用参考方向。定义：

\[
A=\{x\mid D_{new}(x)\ne D_{old}(x)\}
\]

或者利用 `H`：

\[
A=\{x\mid H(x)\ne H(s(x))\}
\]

若：

\[
H(x)=H(s(x))
\]

则旧方向仍然最优，可以复用。

否则该位置的方向需要修改。

## 17. A 的结构性质

`A` 没有理论保证是几何意义上的单一封闭区域。它可能不连通、有孔洞、有细长分支、延伸到很远的
位置，也可能在关键分叉结构中覆盖大部分房间。因此本设计不采用"先求出 A 的边界，再只计算 A"的
路线，而是**通过增量最短路传播，在计算过程中逐步发现 A**。

## 18. 最坏情况

增量 / 参考场算法不能保证每次都比从头建场更省 CPU。

最坏情况下：

\[
A\approx整个房间
\]

此时可能扩展接近全部 2500 个节点，同时还要承担读取参考场、计算残差边权、方向复用判断和额外状态维护等开销，因此可能比完整重建略贵。

可以设置 fallback：

```ts
if (processedNodes > FALLBACK_LIMIT) {
    rebuildFromScratch();
}
```

## 19. `cm` 与 A 的关系

虽然不能数学保证 `A` 很小，但 `cm` 可以显著提高参考场质量。

只有满足：

\[
C_R(T)<c_m
\]

的参考场才参与。

这表示新目标 `T` 与参考目标 `R` 在真实移动成本意义上足够接近。

通常 `cm` 越小：

- 参考目标更接近新目标
- 新旧最短路径树更相似
- `A` 统计上通常更小
- 增量求解通常更划算

但不能形成严格保证。

因此推荐：

```text
cm            → 入口质量控制
fallback limit → 最坏情况止损
```

## 20. 算法方向

不采用"先找一个预先确定的封闭区域 A，在 A 内重算、A 外复用"的路线，改用下列增量传播流程：

```text
已有参考 Cost Field C
        ↓
根据 C 构造残差边权 ρ
        ↓
从新目标 T 在残差图中做增量 Dijkstra
        ↓
搜索过程中判断：H(x) == H(s(x)) ?
        ↓
是：复用参考方向
否：写入新方向
        ↓
逐步发现真正的 affected region A
```

该方法：

- 严格最优
- 可充分利用参考 Cost Field
- 平均情况下可能只修改局部区域
- 最坏情况下退化为接近完整建场
- 可通过 `cm + fallback` 控制工程风险

## 21. 设计结论

1. Cost Field：`Uint16Array(2500)`，约 5 KB。
2. Direction Field：4 bit / cell，约 1250 B。
3. 两种 Field 独立缓存。
4. 方向生成：能主动生成则主动生成，其余位置 Lazy 补齐。
5. 每个 profile 维护 `bestField + bestCost` 两张 2500 数组。
6. `cm` 用真实成本控制参考场最大有效范围。
7. `cmin` 是控制参考场密度的候选机制，是否值得保留仍需结合实际 CPU / 内存收益评估。
8. 参考场复用核心是：用 Cost Field 作为势函数重加权，构造非负残差边权，在残差图中求新目标最短路。
9. affected region 不能预先假设是简单封闭区域，应通过增量传播动态发现。
10. `cm` 提高平均参考质量，fallback 限制最坏额外开销。

## 22. 待决设计事项

1. 残差 Dijkstra 在 Screeps 典型房间中的实际节点展开规模。
2. `cm` 取值与平均 affected region 大小之间的关系。
3. 是否存在比普通 heap 更适合残差边权分布的队列结构。
4. 是否可以利用大量 `ρ=0` 的旧方向边做专门优化。
5. Direction Field 是否应该保存完整方向，还是“继承参考场 + override”的差分结构。
6. fallback 阈值如何选择。
7. `cmin` 是否在真实 workload 中值得保留。
8. 是否存在更强、可严格证明的提前停止条件。

## 结论

> **不把"建立完整新 Cost Field"视为新目标寻路的必经步骤。**

已有参考 Cost Field 作为势函数，把新目标问题转换为残差最短路问题，从而在保持**严格最优路径**的
前提下，只修改参考 Direction Field 中真正受新目标影响的部分。受影响区域不能预先通过简单几何边界
确定，只能在最短路修正传播过程中逐步发现，因此优化重点是：

> **让增量传播在典型情况下尽可能少地访问节点，并在坏情况下快速退化到普通完整建场。**
