## 1. 职责与使用边界

app.config 保存劳动力配置、身体模板、孵化优先级和相关阈值。各领域根据 colony 的发展阶段、运行姿态与预算，结合世界事实确定劳动力需求；`lib.body` 的纯函数展开身体并计算成本、能力与孵化时间；spawnQueue 统一仲裁孵化与空闲续命。

配置不直接执行动作，不保存 creep 任务，也不替代身体与位置核验。新增角色及调整表内参数在本模块维护；涉及模块职责、跨模块契约或里程碑变化时，按根 AGENTS 的章程修订授权规则处理。

<a id="workforce"></a>
## 2. 劳动力配置

### 2.1 按发展阶段配置

| 阶段 | 角色与数量 |
| --- | --- |
| 紧急 | 1–2 个最小采集者，按当前可用能量孵化；采集后直接给 spawn 补能 |
| 早期（RCL 1–3，无 container） | 通用工人。每个 source 分配的 WORK 总数约为 5 × 1.5（含往返损耗），且人数不超过 source 周围可站格数。工作顺序：采集 → 补能 → 建造 → 升级 |
| 静态采矿 | 每个 source 1 个矿工；搬运工按运力公式配置；升级者与建造者按预算配置 |
| storage 经济（RCL 4+） | 同上；搬运工把能量送进 storage；增加 1–2 个补能者，从 storage 给 spawn、extension、tower 补能 |
| link（RCL 5+） | 矿工增加 CARRY，把能量转入 source link；接入 link 的 source 不再配搬运工；升级者从 controller link 取能 |
| 后期（RCL 7–8） | 核心转运由中央枢纽承担（架构 9.7）；RCL8 升级者 WORK 总数不超过 15 |

### 2.2 数量换算

以下初始规则依据[架构附录 A](../architecture.md) 的 F16，运输公式见该文档 12.3。

| 角色 | 规模 |
| --- | --- |
| 矿工 | 每个 source 5 个 WORK（产能 10 能量/tick ÷ 每 WORK 采集 2） |
| 搬运工 | CARRY 总数 = `ceil(2 × 路径长度 × 10 / 50)` / 每个 source |
| 升级者 | WORK 总数 = 升级预算（能量/tick）÷ 1；RCL8 不超过 15 |
| 建造者 | WORK 总数 = 建造预算（能量/tick）÷ 5；没有工地时为 0 |
| 补能者 | CARRY 总数满足在 `T_REFILL` tick 内补满全部 spawn 与 extension |
| 中央枢纽 | 枢纽存在且满足启用条件时配置 1 个，按核心转运需求选择体型，最多 20 CARRY；需求与吞吐以任务积压、补料时限核验 |

<a id="body-templates"></a>
## 3. 身体模板

| 角色 | 重复单元 | 规模规则 |
| --- | --- | --- |
| 最小采集者 | `[WORK, CARRY, MOVE]` | 固定 1 个单元（200 能量） |
| 通用工人 | `[WORK, CARRY, MOVE]` | 能量上限可负担的最多单元，单元数不超过 5 |
| 矿工 | `[WORK×5]` + MOVE；link 阶段加 1 CARRY | MOVE 数取 1–3，按到达时限与能量上限决定；能量上限不足 550 时用可负担的最大 WORK 数 |
| 搬运工 | `[CARRY, CARRY, MOVE]` | 单个不超过所需 CARRY 总数的一半，便于两个分担；上限 32 CARRY |
| 补能者 | `[CARRY, CARRY, MOVE]` | 按补能需求 |
| 升级者 | `[WORK×k, CARRY, MOVE×⌈k/2⌉]` | k 由预算决定，单个不超过 15 WORK |
| 建造者 | `[WORK, CARRY, MOVE]` | 按预算 |
| 近战防御者 | `[ATTACK, MOVE]` | 按威胁（架构 10.7） |
| 远程防御者 | `[RANGED_ATTACK, MOVE]` | 按威胁（架构 10.7） |
| 中央枢纽 | `[CARRY×n]` | `1 ≤ n ≤ HUB_CARRY_MAX`，无 MOVE、无 boost，由相邻 spawn 定向孵化到枢纽格 |

- 单个 creep 不超过 50 个部件。
- 移动角色的 MOVE 比例原则：主要在道路上活动按 MOVE 与其他负重部件 1:2，否则按 1:1；固定工作角色按表中的到达与工作条件选型，中央枢纽不配 MOVE。
- 平时按能量上限与角色规模上限生成满配体型；紧急时按当前可用能量生成最小可用体型。
- 体型展开由 `lib.body` 的纯函数完成，模板与上限写在 `app.config`。身体计算不依赖运行期任务状态。

<a id="spawn-priorities"></a>
## 4. 孵化优先级

| 优先级 | 请求 |
| --- | --- |
| 100 | 紧急采集者（殖民地没有采集者） |
| 95 | 防御者（安全轴为战时） |
| 90 | 补能链断裂时的首个搬运工或补能者 |
| 85 | 矿工（含提前孵化的接替者） |
| 80 | 搬运工 |
| 75 | 中央枢纽 creep 的补位 |
| 70 | 防降级升级者（控制器剩余降级时间低于 `CONTROLLER_DOWNGRADE` 的 50%） |
| 60 | 建造者 |
| 50 | 升级者 |
| 40 | 外矿相关（M4） |
| 30 | 扶持与扩张（M5） |
| 20 | 侦察 |

同优先级按 deadline 先后。姿态配置可以整体调整某类请求的优先级（例如战时降低升级者）。

中央枢纽续命不占用上述优先级：spawn 处理可执行的孵化请求后仍有空闲、能量足够且可完整容纳一次寿命增量时才续命。不提升优先级、不预留窗口、不延迟正常孵化；繁忙导致死亡后按补位请求排队。20 CARRY 时可续命的寿命上限为 1470；其他体型按 `1500 − floor(600/n)` 计算。

<a id="parameters"></a>
## 5. 相关参数

| 参数 | 默认值或上限 | 用途 |
| --- | --- | --- |
| `HUB_CARRY_MAX` | 20 CARRY | 中央枢纽体型上限，未 boost 时容量上限 1000；实际部件数按需求确定 |
| `T_REFILL` | 50 tick | 补能者的运力配置时限 |
| 防降级阈值 | `CONTROLLER_DOWNGRADE` 的 50% | 保留防降级升级及提出相应孵化需求 |

其余角色的规模上限见本文件各表；其他模块内部参数由对应模块设计维护。
