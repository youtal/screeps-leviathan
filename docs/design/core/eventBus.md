# EventBus 设计

交付状态：三种作用域的同步发布订阅、快照派发、订阅者异常隔离、空容器回收、事件注册表与 Runtime 装配已交付；Framework 的插件订阅代理已交付（见 [Framework 设计 §5.2](./framework.md)）。游戏事件的生产不属于本模块，由信息类服务插件负责（见 Framework 设计 §4.2）。

EventBus 在模块之间同步传递离散事实。公共协议由 [contracts/eventBus.ts](../../../src/contracts/eventBus.ts)（总线接口、作用域、监听器）与 [contracts/events](../../../src/contracts/events/index.ts)（事件注册表与载荷推导）发布；模块目录为 `src/core/eventBus`，提供 `createBus` 与事件名常量。

## 1. 定位与边界

- 只负责订阅、取消订阅与发布，不决定游戏业务行为，不生产游戏事件，不访问 Game、Memory 或 RawMemory。
- 模块之间的三种协作方式各有分工：离散事实使用事件，需要返回值的操作使用服务，竞争性动作使用意图（Framework 设计 §2）。
- 订阅表只存在于实例 heap。监听器是函数，无法序列化，也没有跨 global 保存的意义。

## 2. 装配

Runtime 以注入的 LoggerFactory 创建唯一实例（`createBus(logging)`），所有 `ModuleContext` 共享这一条总线，同一应用中的事件因此互通。EventBus 不导入 Logger 的具体实现，也不在缺少依赖时创建隐藏实例。

Framework 为每个插件包装一层代理，规则见 Framework 设计 §5.2：订阅者名自动加插件 id 前缀，订阅限定在插件自己的 setup 中，停用、卸载或 setup 失败后自动取消，回调进入订阅者的错误边界。

## 3. 事件模型

- 事件名是 `分类:事件` 形式的字符串字面量，由 `EventRegistry` 推导出联合类型 `EventType`；未登记的事件名在编译期被拒绝。
- 载荷 `DataByEvent<T>` 由分类公共数据与事件附加数据合并而成，同名字段以事件附加数据为准。例如 `structure:destroyed` 在 `roomName`、`structureId` 之外附加 `ruinId`，供订阅者核验建筑确实已被摧毁。
- 新增事件只需修改注册表。`eventList` 用 `satisfies` 检查每个常量都属于 `EventType`，同时保留各属性的精确字面量类型。
- 载荷不做运行时校验，类型正确性只由泛型保证。

## 4. 作用域与广播规则

| 发布作用域 | 通知的订阅者 |
| --- | --- |
| `global` | global 订阅者 |
| `room`（房间 R） | 房间 R 的订阅者，然后是 global 订阅者 |
| `group`（分组 G） | 分组 G 的订阅者 |

- global 发布不向房间扇出。需要全房间广播时由业务逐个房间发布，避免隐藏的 CPU 成本。
- room 发布上报 global，全局观察者可以用一个订阅接收所有房间的同类事件。
- group 发布不上报 global，也不通知任何房间，使任务组、编队等内部消息与全局事件流隔离。

## 5. 订阅协议

- 订阅键为（作用域、事件名、订阅者名）。同键再次订阅会替换原监听器并记录 warn，暴露“以为注册了两份、实际只剩一份”的问题。被替换的订阅者保留原来的派发位置。
- 取消不存在的订阅只记录 warn，可以重复调用。
- 事件表清空时删除该事件，房间或分组下没有任何事件时删除该房间或分组，global 容器始终保留。heap 占用只与当前有效订阅数相关，与历史上出现过的房间或分组数量无关。

## 6. 派发

- 发布时先为相关作用域取快照（room 发布同时取房间与 global 两份），再依次调用。回调中新增或取消订阅只影响之后的发布，重入发布是安全的。
- 同一作用域内按订阅的插入顺序调用。
- 监听器抛错被捕获并记录 error，不中断本轮派发，也不传播给发布者。
- 返回值是本轮尝试调用的监听器数量，包含抛错者。发布者无法从返回值区分成功与失败，这是隔离订阅者故障的代价。
- 同一个载荷对象按引用依次传给本轮所有订阅者，总线不复制也不冻结；某个订阅者修改载荷，之后的订阅者会看到修改后的值。

## 7. 性能

- 没有订阅者时，发布只做几次 Map 查找（room 发布同时查两个作用域）后返回 0，不分配快照，不生成日志。
- 有订阅者时，快照复制的成本与订阅者数量线性相关，快照只在本轮发布内有效。
- 监听器同步执行，其 CPU 计入发布时刻。在 Framework 中，回调计入订阅者的 `plugin.<id>.<阶段>` 标签，嵌套在发布者的标签之内。
- 订阅、取消与逐订阅者通知的明细使用 info 等级（默认关闭）。等级在作用域创建时定型，每次通知只查询一次；关闭时通知路径不构造任何日志字符串，包括作用域标签。

## 8. 生命周期与失败降级

- 订阅表随实例驻留 heap，可以跨 tick 复用；global reset 后随 Runtime 重建，订阅者需要重新订阅。插件在 setup 中订阅，重新 setup 即恢复订阅。
- 监听器异常只影响该监听器本身；在 Framework 中，失败还会把订阅者标记为本 tick 失败，本 tick 内它不再收到后续事件。
- 同键替换是有意保留的覆盖语义：不同模块使用相同的订阅者名会互相覆盖。Framework 代理以插件 id 作为前缀，避免插件之间的冲突。
