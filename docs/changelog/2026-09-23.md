## TaskScheduler 审计整改

按 [TaskScheduler 工作区交付物审计](../audits/2026-09-23-taskScheduler.md) 关闭 T01–T11、T13–T16，T12 部分关闭（行为写入文档，处置待决定）。三项取舍经确认：任务只用空闲的常规额度并支持单任务每 tick 软上限（缺省不限）；`submit` 只保证实例存在；AGENTS.md §10 的组合根清单加入 TaskScheduler。

- CPU 口径（T01）：`drive` 每开始一片前调用 `cpu.admit()`（普通插件准入口径），任务只用 `limit − reserveCpu` 以内的剩余，不透支 bucket；分片耗时改用 `Game.cpu.getUsed` 差值计量。新增 `TaskOptions.maxCpuPerTick` 与调度器缺省 `defaultMaxCpuPerTick`（不限），达到上限后本 tick 不再开始新分片，让出的 CPU 分给其他任务。
- 硬终止恢复（T02、T03）：清扫中重建任务体在错误边界内进行，body 抛错只让该任务失败；deadline 先于恢复判断；同一实例最多重启 1 次，第 2 次被中断以 failed 结束。
- 实例语义（T04、T06、T10、T11）：`submit` 在任何状态下都返回已有实例，完成的结果不重算、失败与过期保持可见；新增 `release(id)` 用于重算与重试；句柄改为实例的实时视图；实例连续 `retainTicks`（缺省 1000）tick 未被 `submit`/`get` 触碰即回收；进入终态即释放任务体。
- 插件释放时回收任务（T16）：新增 `TaskHost.releaseOwner`，Framework 在停用、熔断、卸载、替换或 setup 失败时调用。
- `drive` 弹出任务后复查状态，同一轮中被取消的任务不再被重新驱动（T07）。
- 文档（T05、T08、T12、T13、T14）：修正示例（任务体是返回生成器的函数）；Runtime、Framework、contracts 的设计与使用说明补入任务调度；写明任务体不能写 Memory、不能提交意图，以及 drive 中发布事件时订阅者失败不计入熔断（是否拒绝发布待决定）；设计文本对齐；更正上一节的集成测试描述。
- 工程（T15）：`src/core/index.ts` 导出 TaskScheduler；AGENTS.md §10 更新；测试注释更正。
- 测试（T09）：TaskScheduler 单元测试 32 项；Framework 任务驱动接入 8 项、Runtime 装配 2 项、编译期回归 1 项；新增私服场景 `leviathan-tasks`（跨 tick 推进与完成后不重算、分片内硬终止后的重启与失败、终止所在 tick 已提交 Memory 的落盘）。

## TaskScheduler 审计第二轮：跨 global 重启记录、bucket 盈余额度与 T12

按 [审计 §10](../audits/2026-09-23-taskScheduler.md#10-第二轮决策与实现2026-09-23) 的决定实现：

- 跨 global 重启记录：`TaskHost` 新增 `persist(tick)`，Framework 在 `MemoryHost.end` 之前调用；Runtime 把 MemoryHost 注入调度器，调度器在内核保留 owner `framework` 下的分区 `tasks` 记录每个存续实例经历的 global reset 次数。连续第 3 次 reset 后重新提交的实例直接以 failed 结束并删除记录；实例结束或被释放后记录随之删除，无人认领的旧记录按 `retainTicks` 清理。只用路径写入，存储不可用时跳过并告警一次。
- bucket 盈余额度：新增 `burstBucket`（缺省 9500，`Infinity` 关闭）。bucket 达到水位时，任务在常规额度之外还可以使用高于水位的盈余，每 tick 至多再用一份 `limit`，并与 `tickLimit` 保持 100 CPU 的距离。
- T12：任务驱动期间事件不进入插件。插件上下文的 `publish` 在 `tasks.drive` 阶段抛错，发布事件的任务以 failed 结束；经 `runtime.bus` 发布的事件不投递给插件订阅者，每种事件告警一次。
- 测试：TaskScheduler 单元测试增至 43 项（盈余额度 5 项、跨 global 记录 6 项），Runtime 装配 1 项，Framework 用例新增 2 项（T12）并更新调用顺序；私服场景 `leviathan-tasks` 增加阶段 4（快照启动新世界后，存续实例的 reset 记录由 0 变为 1）。新增 11 项反向检查。
- 文档：TaskScheduler 设计（依赖、配置、§5.2 盈余额度、§5.7 事件规则、§5.8 跨 global 记录）与使用说明、Runtime、Framework、contracts、Core 架构与集成测试说明同步；设计 §8 移除已决定的事项。

验证：`tsc --noEmit`、`npm test`（Jest 13 套件 255 项；构建工具 7 项、产物 3 项、隔离边界 3 项）、`npm run build`（含不含 `.secret.json` 的临时副本）、`npm run test:integration`（4 个场景）、`git diff --check` 与 Markdown 相对链接检查均通过。未上传游戏服务器。
