# 2026-09-09 更新简讯

- 完成 Framework Memory 显式标脏：插件状态统一通过 `context.persistence.query()` 与 `commit(callback)` 访问，公共持久化接口只保留查询和提交两项能力。
- 仅保留 `critical` 与 `checkpoint` 两个持久化层。未声明持久化的插件不创建 Memory 分区；RoomShortcuts 和路径相关派生缓存继续由各模块闭包管理。
- 每个 Framework 实例仅在首次 loop 解析一次 RawMemory。只有到期 dirty 分区执行原生 JSON.stringify，clean 分区复用缓存片段，完全 clean 的 tick 不调用 `RawMemory.set`。
- 删除递归 JSON 合法性检查与迁移深克隆，插件提交的键值对象采用直接操作 Memory 时的 JSON.stringify 行为。
- 意图回执改为只在当前 global 生命周期的 heap 中保留；插件普通成功 tick 不再持续更新健康状态，避免无业务变化时产生持久化开销。
- Profiler 接入检查点标脏回调；独立 Runtime 默认使用闭包内统计，不再隐式访问全局 `Memory`。
- 补充 Framework、Profiler、Runtime、goto 与 RoomShortcuts 的存储边界文档，并增加关键分层行为测试。
- 验证通过：TypeScript 类型检查、76 项 Jest 测试、4 项构建插件测试、2 项真实打包产物测试、无密钥正式构建和差异格式检查；未执行外部上传。
