# 2026-09-20 更新简讯

## 审计 F1–F3b 整改（MemoryManager）

- F1：Segment 页解析结果按页文本缓存，未变化的页不再每 tick 重复 `JSON.parse`。
- F2：无宿主根对象时缓存非托管根字段的序列化片段；有宿主根对象时保持现取。
- F3：Raw 与 Segment 恢复时校验 payload 为键值对象，异常数据进入 `pending('recovery')` 并记录诊断。
- F3b：主 Memory 序列化文本超过 `RAW_MEMORY_LIMIT` 时拒绝调用引擎写入，保留 dirty 与带体积的诊断。
- 同步更新 MemoryManager 设计文档与使用说明；新增 [整改记录](../audits/2026-09-20-remediation.md)。

## 审计 F4 整改（roomShortcuts）

- 无视野告警由每次调用 `error` 改为按房间只记录一次 `warn`；恢复视野后清除标记。缓存失效语义不变。
- 补充 `structure:built` 增量分支测试（未初始化跳过、重复投递、新类别追加、对象缺失、跨房间），roomShortcuts 语句覆盖率由 64% 提升到 75%。
- 更新 roomShortcuts 设计文档。

## 审计 F5、F6、F8 整改

- F5：`PriorityQueue` 构造时拷贝传入数组，不再改写调用方数组。
- F6：`replaceHtml` 的替换值按字面量写入，键名做正则转义。
- F8：更正 Framework wrappers 缓存注释。

## 审计 F7、F8 收尾（经用户批准）

- F7：`Logger` 契约新增 `isEnabled(level)`；Logger 实现返回作用域定型的等级；EventBus 通知路径在 info 关闭时不再为每个订阅者求值日志模板。属公共契约变更，Logger 设计与使用文档已同步，测试中的 Logger 替身补充该方法。
- F8：`.vscode/settings.json` 取消 Git 跟踪（文件保留在本地，`.gitignore` 已列 `.vscode/`）。
- 详情见[整改记录](../audits/2026-09-20-remediation.md)。

## 审计复审补充：F3b 静默失败路径

- 新增 `MemoryManagerStatus.rawWriteError` 与管理器级写入失败告警，覆盖没有待提交 Raw 分区（如仅宿主根字段超限）的写入失败。
- 整改记录修正：F6 不代表 A11 关闭，A08 仅补充 `structure:built` 子集测试；补全 F5–F8 提交哈希。

## 追加复审 R1–R4 处置

- R1：补充损坏分区恢复流程，区分 Raw 快照重建与 Segment 页恢复；不新增有损重置接口。
- R2：MemoryHost 增加必需的 getStatus 最小诊断；Framework 状态暴露 memory.rawWriteError，保留插件缩减数据后恢复提交的能力。核对官方 driver 的 UTF-16 长度口径并补充汉字、emoji 边界测试。
- R3：条件 delete 无法消除实际删除的形状变化，缺乏性能收益证据，评估后不采纳。
- R4：页观察缓存仅保留信封头，避免重复驻留 payload 对象，补充页变化与清空的缓存失效回归。
- 详见[复审评估与关闭记录](../audits/2026-09-20-remediation.md#9-复审新增项评估与处置)。
