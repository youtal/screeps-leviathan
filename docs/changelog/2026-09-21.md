## MemoryManager 同步分区访问实现

分支 `refactor/memory-manager-v2` 按 [MemoryManager 设计](../design/core/memoryManager.md) §10 落地全部设计项。

- **契约**：`src/contracts/memory.ts` 发布长期访问器（query/get/commit/remove）、深路径类型与 `MemoryHost.getStatus` 的 `loadError/rawWriteError`；移除 `MemoryAccess`、pending 原因、`layer`/`checkpointInterval`/`priority` 与 `deferStartupWindow`。路径类型按实参逐段校验，递归预算 8 段，`MemoryAccessor<any>` 为显式动态入口。类型验证：300 键业务类型上 400 次路径调用使 `tsc` 检查时间增加约 0.5 s、实例化约 8 万次。
- **实现**：`src/core/memoryManager` 重写为 namespace（装载与 schemaVersion 1/旧 leviathan 兼容）、paths（深路径定位）、json（受管 JSON 校验）与主实现；删除 Segment、分配、journal 迁移及 `segments.ts`。分区以片段为序列化单位，空闲 tick 常数时间返回；回调修改的分区收尾完整校验；提交按“平台接受 → 更新基线 → 清脏”执行；生命周期锁以平台真实 tick 为归属。
- **Framework**：loop 重入锁改为带真实 tick 归属，硬终止跳过 finally 后下一 tick 自动恢复；删除启动申请窗口逻辑；`getStatus().memory` 投影 `loadError` 与 `rawWriteError`。
- **测试**：重写 `test/memoryManager.test.ts`（34 项，含以 vm 超时模拟硬终止的恢复用例）与 Framework 的 Memory 集成用例（含 loop 硬终止恢复）；新增 `test/types/memoryPath.types.ts` 类型正负例；产物测试新增真实 bundle 的分区写出与 clean tick 不写盘。
- **集成测试**：删除 `leviathan-segments` 场景；`build/runIntegration.mjs` 额外编译 `src/core` 探针模块并改为写入 `RAW_MEMORY_LIMIT` 元数据；新增 `leviathan-memory` 场景，在 screeps 4.3 私服验证写出、UTF-16 容量、完整提交 CPU、CPU 硬终止恢复（实测 heap 保留）与 global reset 恢复；`leviathan-global-reset` 更新为旧布局导入与装载故障安全模式。
- **文档**：重写 MemoryManager 使用说明；更新设计交付状态、contracts/Framework 使用说明与集成测试说明。
