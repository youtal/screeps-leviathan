## MemoryManager 模块审计整改

按 [2026-09-22 模块审计](../audits/2026-09-22-memoryManager.md) 关闭 M1–M8：

- **M1**：`initialize`/`migrate` 的返回值校验后复制为工作对象，返回模块级常量、共用对象或冻结对象不再导致分区间共享或写入异常。

- **M6**：`Record<number, X>` 可用字符串段访问；`remove` 的可删性区分显式声明键与索引签名，修正字面量 Record 键被误判为不可删的问题。
- **M7**：补充结构错误、调用参数错误、重入与回调内 `remove` 的测试。
- **M8**：更正 `ModuleContext.memory` 注释与 Runtime 使用说明中过时的配置描述。
- **M4、M5**：不修改实现。使用说明新增“提交开销与 CPU 预留”与“共享关系不随持久化保留”，设计 §4.3 同步写明后者。

验证：`npx tsc --noEmit`、`npm test`（Jest 162 项）、`npm run build`、`npm run test:integration`（三个场景）与 `git diff --check` 均通过。未上传游戏服务器。

## MemoryManager 申请失败缓存收窄（N2）

按 [模块审计 §6.4](../audits/2026-09-22-memoryManager.md) 以 A+B 关闭 N2：

- 失败缓存只登记管理器判定的确定性错误（缺少 migrate、同版本历史数据不合规）；initialize/migrate 抛错、返回 thenable 或返回值不合规不再缓存，下一次申请重新运行。暂时性失败在条件恢复后可以自愈，插件场景下经 `recover()` 即可重新申请，无需 global reset。
- 契约、设计 §3/§7 与使用说明写明 initialize/migrate 必须是只依赖输入的确定性函数，并给出申请后补齐游戏状态数据的写法。
- 新增管理器与 Framework 两级回归用例；调整原“失败回调只运行一次”的用例为“重试且每次收到未被污染的副本”。

验证：`tsc`、`npm test`（Jest 170 项）、`build`、`git diff --check` 均通过。未上传游戏服务器。

## Logger 惰性日志内容

分支 `feat/logger-lazy-message`：

- `src/contracts/logging.ts` 新增 `LogContent = string | (() => string)`，六个日志方法都接受字符串或惰性回调；现有字符串调用不受影响。
- `createLogging` 在等级关闭时于解析内容之前返回；开启时回调只调用一次，控制台与邮件共用同一文本；回调抛错丢弃该条日志，非字符串结果按 `String()` 转换。
- 未采用可变参数：实参在调用前求值，省不掉昂贵的参数计算。实测等级关闭时，含 `JSON.stringify` 的消息用可变参数仍需 15.3 µs，惰性回调约 0.03 µs。
- 同步 Logger 设计与使用说明、Core 架构 §10 与 contracts 设计；新增 4 个 Logger 用例与契约类型用例。现有调用点未改动。

验证：`tsc`、`npm test`、`build`、`test:integration`、`git diff --check` 均通过。未上传游戏服务器。
