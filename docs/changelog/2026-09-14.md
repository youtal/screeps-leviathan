## 集成测试：错误口径、失败诊断与两个新场景

- 新增 `test/integration/support/harness.js`：统一正式产物装载（含 `main.js.map` 模块与内存内 heap
  探针）、运行期断言口径与失败现场输出，场景不再各自复制探针。
- 修正错误口径：框架 `report.errors` 只按硬编码模式分类，普通 `throw new Error('...')` 不会进入其中，
  只留在 `report.logs`。场景改用 `assertRuntimeClean()`（框架分类 + 日志抛出型错误扫描），并在失败时
  把抛出型错误前置到异常消息，消除“bot 每 tick 抛异常却只报 `evalInBot` 超时”的误导性诊断。
- 新增 `leviathan-global-reset` 场景：以“Memory 快照 + 新世界”等价表达一次 global reset，验证旧
  `leviathan` 布局与无关根字段只读保留、heap 重建后 Memory 完整继承、未知 `schemaVersion` 时报告诊断
  且不覆盖存储。
- 新增 `leviathan-segments` 场景：验证 Segment 激活后跨 tick 读写、按页隔离，以及 `SEGMENT_CAPACITY`
  （100000 字符）的完整往返；同时实测记录本环境与线上的语义差异（不强制激活、`activeSegments` 恒为
  `null`、超限崩溃而非拒绝），这些路径已在文档标为不可在本环境验证。
- 修正 `docs/testing/integration.md`：引擎日志由 mockup 硬编码写入仓库根 `server/logs/`（框架只覆盖
  `path`，即 `cacheDir`），原文误写为 `test/integration/.cache/`；同步修正排错指引，并补充场景清单、
  共享 harness 与错误口径说明。
- 验证：`npm run test:integration` 三场景全部通过（global-reset 9s / runtime 4s / segments 4s）；
  注入 loop 抛异常的负面对照确认失败信息首行给出真实异常；`npm test` 136 用例与 6 个脚本用例通过。
