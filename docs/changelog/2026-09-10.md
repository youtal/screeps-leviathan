# 2026-09-10 更新简讯

本轮为工作区收敛提交：把 09-08、09-09 两次迭代留在工作区的 Framework 实现、文档、测试与依赖变更一并入库，代码内容与提交前的工作区完全一致，未新增功能。

- 入库 Leviathan Framework 首版实现：`src/core/framework/` 新增生命周期调度、插件注册表、意图通道、Memory 拦截、CPU 准入和错误映射六个职责文件，并导出统一的插件类型与工厂。
- 入库 Framework Memory 分层持久化：插件通过 `context.persistence.query()` 与 `commit(callback)` 访问，仅保留 `critical` 与 `checkpoint` 两层；每个 Framework 实例只在首次挂载时解析一次 RawMemory，后续 tick 复用常驻 heap 根，只有到期 dirty 分区才执行 `JSON.stringify` 与 `RawMemory.set`。
- 应用入口切换到 Framework：`src/app/runtime.ts` 创建唯一实例，`src/app/modules.ts` 以服务插件方式注册 RoomShortcuts，`src/index.ts` 直接导出 `framework.loop`；模块加载阶段只完成注册，Memory 挂载与插件 `setup` 延迟到首次 loop。
- 错误堆栈还原改用同步的 `@jridgewell/trace-mapping`，移除已废弃的 `source-map@0.8.0-beta` 依赖；插件执行、错误映射和日志分别计时，观测失败不再中断业务 tick。
- Profiler 与独立 Runtime 解耦：Runtime 默认把统计放在闭包 heap 中，新增 `markProfilerMemoryDirty` 注入点，需要持久化时必须显式接入 Framework 的访问器与标脏回调；Profiler 不再隐式读写全局 `Memory`。
- `goto` 的上下文类型改为 `PluginContext<GotoMemory>`，用户偏好计划通过统一持久化接口读写；路径、CostMatrix 与 Flow Field 继续只存在于 heap。
- 文档同步：扩充 Framework 设计文档，新增 Profiler、Runtime 设计文档与 Framework、Profiler、Runtime 使用说明，更新 goto、RoomShortcuts 设计说明、文档索引和根 README 入口说明。
- 测试同步：新增 Framework 生命周期、存储、异常与真实打包产物测试，更新 app、profiler、runtime 测试；`npm test` 现在依次执行 Jest、构建插件测试和打包产物测试。
