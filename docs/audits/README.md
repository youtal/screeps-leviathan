审计报告记录特定代码基线的检查结果、风险与建议，不替代模块设计或使用说明。报告中的开发计划需要另行确认后实施。

## 长期接受的风险

以下条目在 2026-09-23 经确认永久挂起并接受，后续审计不再重复提出，也不再安排处理，除非明确要求进一步收窄。

- **A09：业务规模下的性能基线**。现有性能数据来自 Node 中对打包产物的实测与私服集成场景，缺少官方服务器基线。接受理由：测量需要部署到官方账号并长期观测，而当前只有一个业务模块，测得的只是框架骨架的数字。
- **A03：隔离 runner 的上游依赖**。`test/integration/runner` 的旧引擎依赖树有 42 个 npm 风险节点（1 个 critical，来自引擎各包内嵌的 lodash 3.10.1）。接受理由：这些包不进入游戏产物，根依赖扫描为 0；运行期禁网、非 root、只读根文件系统、丢弃全部 capabilities、无宿主挂载；升级会破坏旧引擎，npm 给出的修复建议是降级集成包。本处置取代 [P1 整改记录](./2026-09-19-p1-remediation.md) 中 2026-10-03 的复查安排。
- **A05：RoomShortcuts 建筑事件生产者缺口**。当前 App 没有生产 `structure:built`、`structure:destroyed` 事件的模块。已消失的对象在查询时会被过滤，但新建建筑可能直到默认 5000 tick 租约到期后的下一次查询才被收录。此限制经确认永久挂起并接受，不安排事件生产者实现；需要完整实时建筑列表的调用方应直接查询本 tick 的 Screeps 对象。
