## 2. A01/A02 修复内容

清理目标页使用本次 migration.generation；清理源页使用持久化的 fromGeneration。二者都要求页属于本实例管理范围、没有任何目录仍引用该页，且页面信封与预期身份一致。空页不重复写；不可见或无法证明归属时保留并诊断。

fromGeneration 是兼容性可选字段。旧 copy/verify/switch 可以从仍指向源页的目录补齐；旧 cleanup 已没有可信源代次时不从页自身反推删除权。无法回收会减少可分配页面，但优先保全数据。switch 前再次检查目标页，防止 verify 后页面被替换时删除仍有效的 Raw 源。

迁移冻结由持久 journal 决定，申请分区和每 tick begin 都先检查阶段，再装载数据或执行 migrate。页不可见不能把冻结变成 ready。目录切换后从目标后端恢复，再处理用户声明的数据版本；冻结期不接受业务 commit。

回归覆盖：外来文本、其他 owner/代次/数据版本、配置外页、verify 后替换、正在被其他目录引用的页、可验证的自有副本回收、缺凭证旧 cleanup、三个迁移阶段重启、目标不可见时晚申请及 schema 升级、解冻后的修改持久化。19 项新用例在修复前有 16 项失败、3 项控制用例通过，修复后全部通过。

原审计复现脚本中的 `committed: 2` 是固定输出标签。修复后 access=pending，脚本不会真正执行该写入；不能从随后读出 n=1 再认定丢失已提交修改。正式回归另外验证“解冻后写入 2 → 再 reset → 读出 2”。历史复现脚本不改写，避免污染原证据。

## 3. A03 执行边界

- 日常根 package/lockfile 移除 `screeps-integration-tests` 及旧引擎依赖；根 `.npmrc` 不允许 Git 包。使用 `npm ci --ignore-scripts` 重新安装，已确认宿主 node_modules 不再包含 Screeps 引擎。保留节点的版本未发生升级。
- 独立 runner 保留 `screeps-integration-tests@3.0.0` 和兼容引擎版本，依赖固定于 `test/integration/runner/package-lock.json`，原生编译白名单只作用于该容器。
- 基础 Node 24 镜像固定 SHA-256，构建上下文按固定白名单生成并拒绝符号链接。安装脚本层仅有依赖清单；后续层才复制产物、场景和容量标量元数据。没有宿主源码目录、Git、账户配置或 node_modules 挂载。
- 测试阶段非 root、禁外网、无端口发布、只读根文件系统、丢弃全部 capabilities、禁止提权、限制 CPU/内存/进程数；`/work` 和 `/tmp` 为有界临时内存目录。无 Docker socket 或宿主凭据传入。
- 入口不提供宿主执行回退，不接受任意 Docker 参数。Docker 缺失或隔离执行失败即报错；三个场景在上述约束下通过。

构建安装阶段需要网络，旧依赖脚本仍在容器内执行；Docker 与宿主共享内核，隔离不能消除所有供应链或容器逃逸风险。剩余上游风险只允许在此限定用途下继续追踪，不据此开放完整私服、HTTP/backend 或不可信输入测试。
