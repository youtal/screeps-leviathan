### F1：每 tick 对所有 Segment 页重复 JSON.parse

- 位置：`src/core/memoryManager/createMemoryManager.ts:312`（`refreshObservations`），调用点 1328（`begin`）、1381（`end`）。
- 机制：每次调用遍历全部 `segmentIds`，对非空页执行 `parseEnvelope`（`JSON.parse`），不比较上次文本，页内容未变也重复解析；一个 tick 内两次。
- 证据：10 页、每页约 64 KB，每 tick 2 次解析，实测约 **13 ms/tick**（Node，本机）。免费档 CPU 为 20，约占 65%。
- 触发条件：Segment 中存在数据。当前未使用，属潜在问题。
- 建议：按页缓存上次文本，字符串相同则跳过解析；必要时 `begin` 与 `end` 合并为一次观察。

### F2：Raw 写入重复序列化非命名空间根字段

- 位置：`src/core/memoryManager/namespace.ts:364-373`（`serialize`）。
- 机制：命名空间部分有片段缓存，但其余根字段（如旧的 `creeps`、`rooms`）每次写入都逐键 `JSON.stringify`，无缓存。任何 critical 分区每 tick 为脏，即每 tick 全量重新序列化。
- 触发条件：主 Memory 保留了这类根数据。默认配置不读取宿主 `Memory`，仅保留加载时快照，但快照同样每次序列化。
- 建议：对未变化的根字段缓存序列化片段，或在加载时判断并提示保留键的体积。

### F3：加载持久数据时不校验 payload 形状

- 位置：`namespace.ts:75`（`validateRawPartition` 不检查 payload 类型）；`createMemoryManager.ts` 的 `applyVersion` 在版本一致时直接放行。
- 复现：raw 分区 payload 为 `5`、`"str"`、`[1]` 时 `access()` 返回 `ready` 且 `query()` 返回该值；payload 为 `null` 时永远 `pending: loading`，没有 `recovery` 诊断，也不会自愈。
- 影响：契约要求分区为键值对象，只有 `initialize`/`migrate` 的返回值做了校验。Memory 被手工编辑或外部损坏时，业务会拿到非对象数据，或静默卡住。
- 建议：在 `validateRawPartition` 与 Segment 信封解析处校验 payload 为普通对象，不合格按 `recovery` 处理并写入诊断。

### F3b：主 Memory 写入无体积保护

- Segment 有 `SEGMENT_CAPACITY`（100_000）检查，主 Memory 序列化后没有大小检查（引擎上限 2 MB）。任一 Raw 分区无上限增长会使整串写入失败并逐 tick 重试。
- 建议：写入前检查长度，超限时记录告警并按分区诊断，而不是整串失败。

### F4：roomShortcuts 无视野时报 error 并清缓存

- 位置：`src/modules/roomShortcuts/createRoomShortcuts.ts:290`。
- 机制：无视野房间的每次 getter 调用都 `log.error` 并 `invalidate`。`error` 默认开启，`notify` 策略开启时还会触发邮件。循环中查询多个房间会刷屏；恢复视野后整房间重新扫描。
- 建议：返回空结果，仅按房间限频告警；对短时失去视野可保留缓存到租约到期。

### F5：`PriorityQueue` 改写传入数组

- 位置：`src/utils/priorityQueue.ts:125`（`this.heap = arr || []`，随后原地 heapify）。
- 复现：传入 `[5,3,9,1]`，构造后变为 `[1,3,9,5]`，此后每次 `push` 继续改写该数组。
- 建议：构造时拷贝，或在注释与契约中明确所有权转移。

### F6：`replaceHtml` 替换串未转义

- 位置：`src/utils/console/utils.ts:46`。
- 复现：内容 `cost $& and $1 and $$` 输出为 `cost {content} and $1 and $`。占位符 key 也未转义就拼入 `RegExp`。
- 关系：与 A11（控制台 HTML 信任边界）同类。
- 建议：改用函数式替换 `() => value`，对 key 做正则转义。

### F7：EventBus 关闭日志时仍拼接字符串

- 位置：`src/core/eventBus/createBus.ts:251` 等 `log.info(\`...\`)`。
- 机制：模板字符串在调用前求值，与日志等级无关。实测 60 万次通知约 177 ms（约 0.3 µs/次），当前可忽略，事件量上升后累计。
- 建议：用惰性日志或先判断等级。

### F8：注释与实现漂移、仓库卫生

- `createFramework.ts:58` 注释称 wrappers 在 Profiler 延迟就绪时清空，实际从未清空。
- `.vscode/settings.json` 已被跟踪，而 `.gitignore` 列有 `.vscode/`。
- `MAX_GROUP_EVENTBUS_TTL` 未被引用（`setting.ts` 自己已说明，符合设计，不计缺陷）。
