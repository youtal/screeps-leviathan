## 已完成

[模块入口](../../src/kernel/memory/index.ts)及其余八个实现文件提供平台接管、分区与实体私有切片、路径访问、输入复制、版本迁移、标脏缓存、失败重试、实体回收及尺寸快照。文件分工与宿主调用顺序见[模块设计](../design/kernel/memory.md)。

提交先生成完整候选文本，再写入并发布缓存；下一 tick 比较待确认文本，检测驱动收尾丢弃。不访问平台私有 `_parsed`。空存储显式初始化；外来、损坏或未知 schema 拒绝覆盖。开发期抽查可发现绕过访问器的未标脏修改。

维护预算在同一 tick 的多次调用之间累计。creep 回收使用相邻两个 tick 的缺席事实；房间回收需要宿主完整提供归属、保护和最后观测事实；删除整条记录使旧访问器失效。

## 验证证据

`npm run check` 通过：类型检查通过，8 个测试套件共 128 项测试通过，构建通过。新增 Memory 测试 34 项，位于 [accessor.test.ts](../../test/kernel/memory/accessor.test.ts) 与 [lifecycle.test.ts](../../test/kernel/memory/lifecycle.test.ts)。

- 契约测试：路径安全、对象/数组限制、复制隔离、异常 update 保留部分修改、JSON 非法值拒绝、初始化失败及迁移失败重试。
- 跨 tick 测试：global 内一次解析、干净 tick 无写入、只编码脏单元、reset 后完整编码、写入异常及驱动收尾拒绝后的重试。
- 生命周期测试：实体回收、维护预算、房间保护及过期阈值、惰性迁移、旧访问器失效、未声明单元和其他根字段保留。
- 缓存验证：按单元包络统计 JSON.stringify 次数；60 tick 确定性写入序列逐次与全量 JSON.stringify 文本比较。未把 Node 耗时解释为 Screeps CPU 收益。
- 容量与诊断：硬上限拒绝写入、告警回调抛错不阻止合法提交、只读引用违规修改抽查。
- 测试宿主显式传播平台替身的 tick.error；平台收尾异常单独断言，避免用户代码异常被吞掉造成假阳性。

平台接管与收尾行为的公开源码依据见模块设计，以上运行结果来自严格平台替身，不是真实私服或 CPU 强制中断实验。
